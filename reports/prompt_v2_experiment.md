# 光伏预测豆包提示词优化：初步验证

## 目标

在简化 PVWatts 物理基线之上，用豆包大模型对次日发电量做**小幅、可追溯的误差修正**。此处的“月预测”是逐日次日预测的月累计回测，不是月初一次性预测整月。演示站点为香港 HKUST SQ1，尚不是上海现场数据。

## 与初版提示词的区别

初版给豆包物理预测、天气预报和最近真实发电量，允许输出 0.6–1.4 的修正系数。它缺少“此前预测到底偏高还是偏低”的证据，容易凭概括性的理由上调或下调。

[新版完整提示词](../prompts/pv_correction_v2.md)按下面的顺序约束模型：

1. **划定时间边界**：目标日使用前一日 00Z 发布的 GFS 天气预报；真实发电量最多到目标日前两日。模型只能读取输入 JSON 中的数据。
2. **给出可比的历史误差**：输入最近 14 个已结算日的“当时发布的物理预测、实际发电量、预报辐照度”及比值，并列出辐照量相近日期的统计量。
3. **默认相信物理基线**：样本少、误差方向混杂或相似天气日不足时，要求系数为 1.000。若存在稳定偏差，也至少向 1.000 收缩 75%。
4. **限制输出并保留依据**：修正系数限定在 0.94–1.06，返回置信度、实际引用的历史日期和简短理由。接口采用严格 JSON Schema，脚本再检查日期与系数范围。

物理基线已经利用此前已知的现场天气和实绩做滚动校正。新版提示词明确提醒模型不要对同一站点偏差重复修正，也不要把历史实测天气当作目标日天气。

## 真实 API 回测

三组方法使用同一批 GFS 次日预报和同一站点实绩。豆包型号均为 `doubao-seed-2-1-pro-260915`；V1、V2 分别是真实 API 返回结果。10 月在新版提示词固定之后进行，作为留出月份。

| 月份 | 物理日 MAE | V1 日 MAE | V2 日 MAE | 物理月累计绝对误差 | V2 月累计绝对误差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2023-08 | 29.35 kWh | 29.56 kWh | 29.80 kWh | 75.08 kWh | 45.50 kWh |
| 2023-09 | 32.80 kWh | 33.00 kWh | 32.32 kWh | 160.39 kWh | 141.91 kWh |
| 2023-10（留出） | 18.20 kWh | 未调用 | 18.06 kWh | 125.09 kWh | 84.52 kWh |

三个完整月份共 92 天，物理基线日 MAE 为 **26.718 kWh**，V2 为 **26.663 kWh**，仅降低 **0.055 kWh**。8 月的逐日误差反而增加。因此目前不能宣称提示词带来了稳定或显著的日预测精度提升。10 月留出月的结果仅说明这个思路值得保留并继续验证。

现有私有 React 演示平台仍展示初版 8 月回测；V2 保留为独立实验，不替换线上默认预测，以免把单月改善误认为已验证的精度提升。

## 建议给导师的表述

> 初步建立了“GFS 天气预报—光伏物理模型—豆包大模型受限误差修正”的演示链路。提示词要求模型基于预测发布时可获得的历史预报误差进行保守修正，并输出证据与置信度。三个月公开数据回测表明，在部分月份可改善日误差和月累计误差，但收益尚不稳定。后续获得项目现场数据后，将补齐组件参数、云量及降水等天气信息，扩展跨月份、跨站点验证，再确定大模型修正策略。

## 复现

原始公开数据与 GFS 归档已下载并处理。结果位于本地 `data/processed/`（已被 Git 忽略）。运行：

```bash
.venv/bin/python scripts/evaluate_prompts.py
```

按需重新调用豆包时，在根目录 `.env` 配置 `ARK_API_KEY` 后运行：

```bash
.venv/bin/python scripts/run_doubao_v2.py --forecast-file gfs_oct2023.json --cache-file doubao_predictions_v2_oct2023.json --history-file gfs_backtest.json --history-file gfs_sep2023.json
```
