# 步骤 12：仅监督类别 token 的 9B 微调（运行前固定）

## 假设与已知限制

步骤 9 的 `mlx-lm 0.32.2` 训练对完整 assistant 回复计算损失。Qwen3.5 模板的 assistant 回复包含 `</think>`、换行、A/B/C 和消息结束标记；`--mask-prompt` 只遮住提示前缀，不单独只保留类别 token。对验证样本检查发现，完整训练序列的 **`enable_thinking=False` 生成前缀**恰好是类别 token 前的真实前缀，因此步骤 9 的推理位置正确；但原日志的验证损失 0.183 包含容易预测的模板标记。事后用三类受限概率计算 184 条验证样本的**类别交叉熵**，未微调基座为 1.1685，旧 adapter 为 1.0856，三类均匀概率的值为 $\ln3\approx1.0986$。旧 adapter 的类别学习较弱，与修正方差很小相符。

本轮假设：若梯度只来自真正的 A/B/C 类别 token，而不来自结构标记，模型可能学到更多与逐日残差相关的信息。**这是运行前的待检验假设，不保证 MAE 改善。**

## 唯一训练改动

复用步骤 9 已固定的 890 条训练、184 条验证 SFT，manifest SHA-256 `4da10cf8c060aa5e2465db1eac8a62e69055f83f761ea71ebdab45a19ac96f51`，提示词 SHA-256 `4098a64de03d2bae1cd2b35307faee82022feca2715e5ff15dc806fd1436ee0c`，量化基座两块权重哈希见步骤 9 方案。A/B/C 边界与训练组中位残差、输入特征、最后 2 层 rank 8 LoRA、batch 1、学习率 $10^{-5}$、最大 512 token、种子 42 和 **890 次更新**均不改；从相同基础权重重新训练，不从旧 adapter 继续。

自定义 `ChatDataset.process`：用 `enable_thinking=False` 对 system/user 消息生成前缀，核验其与完整 system/user/assistant 序列的精确 token 前缀一致，再仅保留紧随其后的一个 A/B/C 类别 token，返回 `(prefix + label, len(prefix))`。`mlx-lm` 的 `default_loss` 对 `(offset, sequence_length]` 的目标位置计交叉熵，因此这一返回值应使每条样本**恰有一个受监督目标 token**。训练前对训练和验证全样本验证前缀、标签及受监督 token 数，保存哈希；若最长样本或内存不满足要求，先保留失败记录再处理。最终权重仍用第 890 步，不能事后选择中间检查点。

## 评价与边界

使用与步骤 9 **完全相同的** A/B/C 三 token 限制 softmax、训练组中位残差概率加权、条件物理锚点和裁剪规则，先对 184 条旧验证样本计算类别交叉熵、MAE、RMSE、偏差及逐站结果，并与旧 adapter、未微调基座和条件物理比较。验证集已经多轮使用，改善只能作为探索性证据。

无论验证结果好坏，另对已评分过的 236 条旧测试输入运行一次**事后诊断**，同时报告排除意外暴露首日的 232 条及完整 236 条。旧测试集已用来分析旧模型偏差，因此任何 v4 测试改善**不具有新的独立确认意义**；不得把它写成第二次独立测试。后续可靠结论需要新的未见日期或外部场站。

对比的首要问题是“仅监督类别 token 是否提升类别交叉熵及发电量 MAE”；若类别交叉熵下降而 MAE 不降，说明输出分档或数值还原仍需改进。若 MAE 改善但旧测试期无改善，说明跨季节泛化仍不足。完整失败、版本、模型与预测哈希均写入结果报告。
